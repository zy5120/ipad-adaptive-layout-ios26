# 带精美 TabView 的 App 适配要点（来自鱼律实战）

适用：目标 App 已有“精美 TabView”（独立搜索标签 + 底部长条操作按钮 + 底部搜索），要叠加本技能的双模式（横屏右侧副屏）。

## 当前范围（鱼律实战进度）

- 已适配：`.fullScreen` 详情类页面（主对象详情、关联列表、文档详情等），含副屏搜索、焦点跟随、旋转恢复。
- 未适配：`.sheet` 轻量弹层类页面（快速选择器、快捷输入、临时弹层）——后续按 `DisplayMode.sheet` 走副屏 / 弹层双路径。

## 核心冲突

精美 TabView 的控件（搜索、长条按钮）是 iPhone 式底部控件，塞进 35% 左栏后与右侧副屏“分家”：点搜索在左栏展开，但内容在副屏。解法：控件按“焦点”跟随主屏或副屏。

## 要点

1. **焦点概念**：共享状态加 `focusedPane`（main / sidebar）。主屏内容区触摸/滚动 → main；打开详情 → sidebar。
2. **焦点手势**：用 `DragGesture(minimumDistance: 0).onChanged`（`onEnded` 会被滚动吞掉，不灵敏）；只挂在内容区，不挂标签栏（否则点搜索按钮会把焦点抢回主屏）。
3. **长条按钮**（tabViewBottomAccessory）：横屏且焦点在副屏、副屏有详情对象 → 显示该对象的主操作（编辑 / 添加子项 / 关联等）；否则显示主屏当前页按钮。打开详情时显式置 `focusedPane = .sidebar`。
4. **搜索**：横屏点搜索 → 搜索改在右侧副屏呈现（左侧保持当前主标签）。焦点在副屏详情 → 按详情当前子标签搜该对象内容；否则搜主屏当前页。搜索界面用系统原生 `.searchable`（Liquid Glass，自带灵动动画）；切换主标签时退出搜索。
5. **搜索结果联动**：点搜索结果 → 关闭搜索并把详情同步到全局状态（旋转不丢）。
6. **紧凑模式分区**：详情页内容加 `.environment(\.horizontalSizeClass, .compact)` → 隐藏各页面右上角与长条按钮重复的旧按钮；**搜索界面本身保持宽屏**（否则原生搜索框会消失/跑偏）；搜索内容区可单独加紧凑模式隐藏残留按钮。
7. **只保留一个关闭按钮**：副屏搜索只保留一个关闭 X（放搜索框旁）；页面自身右上角按钮在搜索态一律隐藏（删除、加号等按 `!embeddedSearch` 或紧凑模式隐藏）。
8. **navigationDestination 必须挂在 NavigationStack 内部**：挂在栈外会导致“状态已更新但推不进去”（旋转恢复等逻辑看似执行了却不生效）。
9. **副屏内容切换要强制重建**：详情视图把对象 / 子标签存在 `@State`，切换对象时 SwiftUI 复用同一视图 → 显示旧内容。用 `.id("\(对象标识)|\(子标签)")` 强制重建（等效“关掉旧的、展示新的”）。
10. **旋转恢复**：每个主标签都要注册恢复联动（含 tabIndex 与来源标签记录），从任一标签进入的详情旋转后都能恢复，不能漏挂。

## 铁律补充

- **副屏开关不要限制设备**：`showSidebar = isLandscape`（不判断 `userInterfaceIdiom`），否则 iPhone 横屏只拉伸、不出副屏（用户认可 iPhone 横屏与 iPad 一致出副屏）。
- 副屏左上角 / 搜索框旁只保留一个关闭 X；页面自身右上角按钮在副屏全部隐藏。
- 切换主标签 → 焦点回主屏、退出副屏搜索。
- 从列表入口进入详情时，打开与该入口对应的子标签（与竖屏行为一致），而不是默认第一个标签。
